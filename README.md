# SoroushPlus — پشتیبان‌گیری چت‌های Splus.ir

<div dir="rtl">

**فارسی** | [English](README.en.md)

یک ابزار دسکتاپ که از **حساب کاربری خودتان** در [Splus.ir](https://web.splus.ir/) (پیام‌رسان
سوروش) نسخهٔ پشتیبان تهیه می‌کند. با Selenium وارد وب‌کلاینت می‌شود، فهرست چت‌ها را طی می‌کند و
همه‌چیز را به‌صورت JSON به‌همراه فایل‌های اصلی روی سیستم ذخیره می‌کند.

دو رابط کاربری روی یک موتور مشترک دارد:

| حالت | فایل اجرا | رابط |
|---|---|---|
| **گرافیکی (پیش‌فرض)** | `main.py` | پنجرهٔ Tkinter با دکمه، تنظیمات و لاگ زنده |
| **خط فرمان** | `scraper.py` | پرسش‌های تعاملی در ترمینال |

---

## امکانات

- **ورود بدون وارد کردن رمز عبور** — خودتان در پنجرهٔ Chrome وارد می‌شوید و ابزار فقط بعداً
  توکن نشست را استخراج می‌کند؛ رمز عبورتان هرگز به برنامه داده نمی‌شود.
- **ماندگاری توکن** — توکن‌ها در فایل محلی SQLite با نام `splus.db` ذخیره می‌شوند، بنابراین
  معمولاً فقط یک بار لازم است وارد شوید (اعتبار حدود ۳۰ روز).
- **پیمایش فهرست چت‌ها** — حرکت خودکار روی لیست مکالمات با تلاش مجدد، رفرش هنگام خطا و
  رد کردن کانال‌های تبلیغاتی.
- **انتخاب دامنه** — همه / خصوصی / گروه‌ها / کانال‌ها.
- **محدودیت پیام هر چت** — سقف تعداد پیام برای هر چت، یا بدون محدودیت.
- **دانلود گزینشی رسانه** — فعال/غیرفعال کردن مستقل استیکر، فایل، ویدیو، تصویر، صدا و آلبوم.
- **خروجی JSON ساخت‌یافته** — اطلاعات چت و همه پیام‌ها (نوع، متن، زمان، فرستنده، نام/حجم
  فایل، مدت‌زمان و…) در یک فایل `chat_data.json`.
- **رسانه و آواتارها روی دیسک** — هر چت پوشهٔ خودش را با فایل‌های دانلودشده و تصویر پروفایل
  دارد.
- **قابل ادامه** — اجرای دوباره با داده‌های موجود ادغام می‌شود و چت‌ها/پیام‌های قبلاً پردازش‌شده
  را رد می‌کند.
- **مخفی یا نمایان** — مرورگر را در حالت headless اجرا کنید یا *Debug mode* را روشن کنید و
  کارش را ببینید.
- **توقف امن** — دکمهٔ **Stop** در رابط گرافیکی، درایور را وسط کار می‌بندد.

## پیش‌نیازها

- **Python نسخهٔ 3.9 یا بالاتر**
- **Google Chrome** (دراور به‌صورت خودکار توسط `webdriver-manager` دانلود می‌شود)
- دسترسی به اینترنت — هم برای دانلود `chromedriver` و هم برای اتصال به `web.splus.ir`

## نصب

```bash
git clone https://github.com/p-a-x-e-m/SoroushPlus.git
cd SoroushPlus
pip install -r requirements.txt
```

`requirements.txt` شامل دو وابستگی مستقیم است، با نسخهٔ دقیق (pin‌شده):

```
selenium==4.31.0
webdriver-manager==4.0.2
```

برای نصب کاملاً تکرارپذیر، از فایل قفل استفاده کنید — همهٔ وابستگی‌های غیرمستقیم (از جمله
`requests`) در آن pin شده‌اند و هیچ هشدار امنیتی شناخته‌شده‌ای ندارند:

```bash
pip install -r requirements.lock.txt
```

## روش استفاده

### حالت گرافیکی

```bash
python main.py
```

1. روی **Manual Login** بزنید — پنجرهٔ Chrome روی `web.splus.ir` باز می‌شود.
2. با حساب خودتان وارد شوید، صبر کنید صفحهٔ اصلی کامل لود شود، بعد در پنجرهٔ بازشو
   **Confirm Login** را بزنید. تا زمان تأیید، مرورگر را نبندید.
3. وضعیت باید به `Authenticated ✓` تغییر کند و دکمهٔ **Start Scraping** فعال می‌شود.
4. تنظیمات (پایین) را انتخاب کنید و **Start Scraping** را بزنید.
5. پیشرفت را در نوار وضعیت (`N chats processed`) و پنجرهٔ لاگ دنبال کنید. **Stop** اجرای
   جاری را به‌صورت امن تمام می‌کند.

### حالت خط فرمان

```bash
python scraper.py
```

به‌ترتیب از شما می‌پرسد:

1. حداکثر تعداد پیام برای هر چت (`0` یعنی بدون محدودیت)
2. نوع چت — `1` همه، `2` خصوصی، `3` گروه‌ها، `4` کانال‌ها
3. چه نوع محتوایی دانلود شود (برای هر کدام `y`/`n`): استیکر، فایل، ویدیو، تصویر، صدا، آلبوم

برای اجرای بدون پرسش (غیرتعاملی)، از فلگ‌ها یا متغیرهای محیطی استفاده کنید (فهرست کامل در
`.env.example`):

```bash
python scraper.py --max-messages 500 --tab 3 --video n --album n
SPLUS_MAX_MESSAGES=500 SPLUS_TAB=3 python scraper.py
```

## راهنمای تنظیمات

| تنظیم | کجا | مقادیر | توضیح |
|---|---|---|---|
| Debug mode | چک‌باکس GUI | روشن / خاموش | **روشن** = Chrome نمایان است (برای ورود یا عیب‌یابی). **خاموش** = Chrome با `--headless=new` اجرا می‌شود. |
| Max messages per chat | فیلد GUI / پرامپت CLI | `0` یا عدد مثبت | `0` = بدون محدودیت؛ در غیر این صورت بعد از این تعداد پیام در هر چت متوقف می‌شود. |
| Chat type | دکمه‌های رادیویی GUI / پرامپت CLI | `1` همه · `2` خصوصی · `3` گروه‌ها · `4` کانال‌ها | کدام تب از فهرست مکالمات پیمایش شود. |
| Download options | چک‌باکس‌های GUI / پرامپت‌های CLI | sticker، file، video، image، audio، album | کدام نوع محتوا واقعاً دانلود شود؛ برای رد کردن، تیکش را بردارید. |

## ساختار خروجی

همه‌چیز در پوشهٔ `output/` کنار اسکریپت‌ها ذخیره می‌شود:

```
output/
├── chat_data.json          # اطلاعات همهٔ چت‌ها و پیام‌ها
└── <chat_id>/
    ├── <chat_id>_avatar.png
    ├── <message_id>_0.pdf   # فایل‌های دانلودشده، نام‌گذاری‌شده بر اساس پیام
    ├── <message_id>_1.jpg
    └── ...
```

فایل `chat_data.json` دو کلید سطح‌اول دارد:

```jsonc
{
  "chats": [
    {
      "id": "123456789",
      "title": "گروه پروژه",
      "last_message": "فردا می‌بینمت",
      "timestamp": "2026-09-28T14:03:11.120000",
      "avatar_path": "<project>/output/123456789/123456789_avatar.png"
    }
  ],
  "chat_data": {
    "123456789": [
      {
        "message_id": "987654",
        "sender_type": "other",
        "content_type": "image",
        "timestamp": "1758999999",
        "date": "2026-09-28 14:00:00",
        "text_content": null,
        "media_path": "<project>/output/123456789/987654_0.jpg",
        "file_name": null,
        "file_size": null,
        "duration": null,
        "title": null,
        "artist": null,
        "call_status": null,
        "audio_type": null
      }
    ]
  }
}
```

مقدار `content_type` یکی از `text`، `image`، `video`، `audio`، `file`، `sticker`، `emoji`،
`album`، `call`، `unknown` است.
مقدار `sender_type` برابر `own` یا `other` است.

## احراز هویت

1. در اجرای اول (یا با **Manual Login**) یک پنجرهٔ Chrome واقعی روی `https://web.splus.ir/`
   باز می‌شود.
2. شما مثل همیشه وارد می‌شوید. برنامه نشست را از `localStorage` می‌خواند:
   `dc2_auth_key`، `dc2_auth_key_bc`، `dc2_hash`، `server_salt` و همچنین `user_id` / `dc_id`
   از `user_auth`.
3. این مقادیر در پایگاه‌دادهٔ SQLite با نام **`splus.db`** در ریشهٔ پروژه ذخیره می‌شوند و
   `expires_at` آن‌ها **۳۰ روز** بعد تنظیم می‌شود.
4. در اجراهای بعدی، توکن‌ها دوباره داخل `localStorage` قرار می‌گیرند و صفحه رفرش می‌شود؛
   بنابراین پنجرهٔ ورود باز نمی‌شود.

اعتبار ذخیره‌شده در هر اجرا با تاریخ انقضا بررسی می‌شود: بعد از تمام‌شدن ۳۰ روز، ابزار
دوباره از شما ورود می‌خواهد و نشست مرده را تکرار نمی‌کند.

**برای بازنشانی احراز هویت**، فایل `splus.db` را حذف کنید و دوباره از **Manual Login**
استفاده کنید. در حالت خط فرمان، ابزار تا پنج دقیقه منتظر می‌ماند تا ورودتان را در مرورگر
بازشده تمام کنید.

> فایل `splus.db` را خصوصی نگه دارید — هرکسی که به آن دسترسی داشته باشد می‌تواند از نشست شما
> استفاده کند. روی macOS/Linux این فایل فقط برای مالک قابل خواندن ساخته می‌شود و در
> `.gitignore` آمده تا هرگز کامیت نشود. روی Windows دستور `chmod` چنین چیزی را بیان نمی‌کند،
> پس فایل دسترسی‌های پوشه را به ارث می‌برد — آن را داخل پوشهٔ کاربری خود نگه دارید و ترجیحاً
> از یک درایو رمزنگاری‌شدهٔ کامل استفاده کنید.

## ادامه دادن و محدودیت‌ها

- **ادامه**: فایل `output/chat_data.json` هنگام شروع خوانده می‌شود. شناسه‌های چت و پیام
  قبلاً شناخته‌شده رد می‌شوند و نتایج جدید با داده‌های موجود ادغام می‌شوند — اجرای چندباره،
  یک پشتیبان انباشته می‌سازد.
- **سقف ۱۰۰ چت**: پیمایش بعد از ۱۰۰ چت در هر بار اجرا متوقف می‌شود
  (`len(self.chats) >= 100`).
- **کانال‌های تبلیغاتی** (وجود `.AdvertisementIcon` در لیست) رد می‌شوند.
- **دانلود رسانه** حداکثر ۶۰ ثانیه برای هر فایل صبر می‌کند و فایل‌های ناقص
  (`.crdownload` / `.part` / `.tmp`) را پاک می‌کند.
- **رفتار خطا/تلاش مجدد**: چند خرابی پیاپی باعث رفرش صفحه می‌شود؛ چت‌های ناموفق در اجرای
  بعدی دوباره بررسی می‌شوند.

## رفع مشکل

| مشکل | راه‌حل |
|---|---|
| `Authentication failed` / «No valid tokens found» | روی **Manual Login** بزنید، وارد شوید، صبر کنید صفحه کامل لود شود، بعد **Confirm Login**. |
| Chrome بالا نمی‌آید / خطای دراور | مطمئن شوید Google Chrome نصب است و اینترنت دارید (دراور را `webdriver-manager` دانلود می‌کند). |
| هیچ اتفاقی نمی‌افتد | **Debug mode** را روشن کنید تا Chrome به‌جای headless با پنجره اجرا شود. |
| بعد از مدتی «No valid tokens found» | توکن ۳۰‌روزه منقضی شده — دوباره احراز هویت کنید (یا `splus.db` را حذف کنید). |
| دانلودها تمام نمی‌شوند | بررسی کنید `output/<chat_id>/` قابل نوشتن است و فضای کافی دارد؛ اجرا را تکرار کنید. |
| نیاز به پایان زودهنگام | در رابط گرافیکی **Stop** را بزنید — دراور بسته می‌شود و داده‌های جمع‌آوری‌شده ذخیره می‌شوند. |

## توسعه

```bash
python -m unittest discover -s tests -v   # اجرای تست‌ها

pip-audit -r requirements.lock.txt        # آدیت وابستگی‌ها
```

همین سه بررسی در CI روی هر push و pull request اجرا می‌شوند.

## نکات و اطلاعیه

- این ابزار برای **تهیهٔ پشتیبان از حساب خودتان** است. فقط با حسابی وارد شوید که متعلق به
  شماست یا صراحتاً اجازهٔ استفاده از آن را دارید.
- خودکارسازی وب‌کلاینت ممکن است با شرایط استفادهٔ Splus در تضاد باشد. مسئولانه استفاده کنید،
  سرعت پیمایش را معقول نگه دارید و به حریم خصوصی دیگران و قوانین محل زندگی‌تان احترام
  بگذارید.
- پیام‌ها و رسانه‌های جمع‌آوری‌شده متعلق به صاحبانشان هستند — آن‌ها را بازنشر ندهید.
